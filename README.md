# БЕЛВЭБ — прототип открытия счёта на основе TechUI

Отдельный интерактивный прототип: ИП/юридическое лицо, условные поля, клиентская проверка формата, отправка в демонстрационный обработчик и экран результата. Не отправляет формы в банк. Секреты исходного сайта не используются и не включены в проект.

## Запуск

```sh
npm run dev -- --host 127.0.0.1
```

## Проверки

```sh
npx tsc --noEmit
npm run build
```

Основной интерфейс — `app/page.tsx`, оформление и токены — `app/globals.css`. Логотипы взяты с исходного сайта. Полный Manrope с кириллицей — из официального репозитория Google Fonts (лицензия OFL в public/assets/manrope-OFL.txt). Результаты аудита, границы проверки и отличия от полноценной интеграции описаны в [UX-AUDIT.md](UX-AUDIT.md).

Данные формы хранятся только в состоянии React текущей вкладки; обновление страницы очищает их.

## Полная анкета

После «Открыть счет» открывается «Заявление на комплексное обслуживание». Для ИП и юридического лица перенесены исходные вопросы, ОКЭД, валютные счета, пакеты услуг, зарплатный проект, выбор офиса, документы и согласия. Данные и утверждённые тексты сохранены в `app/source-content.json` и `app/source-copy.json` без редакторских изменений. Компоненты сверены с Solar 1.0 (`XvjAEoJqExd4XwTu5Nby0P`, Inputs Outline `2775:45254`).

Введённые данные и выбранные файлы остаются в памяти вкладки. МСИ, камера, биометрия, государственные реестры и отправка заявки в банк не вызываются. Дополнительной итоговой сводки нет. «Отправить заявку» вызывает демонстрационный POST /api/applications и открывает документы для подписания.

## UX-итерация

Выбор пакета отделён от его настроек. Описание раскрывается одновременно для трёх пакетов; одинаковые характеристики выровнены по строкам. Состояние зарплатного проекта сохраняется отдельно для каждого пакета. Офис требует явного выбора.

Ошибки отображаются рядом с полями; после проверки фокус переходит к первому незаполненному полю. Общая сводка ошибок удалена. Исходные JSON с согласованными формулировками не менялись.

## Компактная анкета и завершение

Поля используют Medium 48 px из Solar, карточки — уменьшенные отступы, согласия — полный текст с выровненными маркерами и интервалами 4 px.

Во время отправки форма блокируется от повторных действий. Ошибка оставляет ответы и файлы для повторной попытки. При успехе открывается продолжение сценария подписания. Сервер проверяет структуру и возвращает демонстрационную квитанцию 202. Он не сохраняет заявки, не загружает содержимое файлов и не запускает банковскую обработку. В запрос передаются ответы и метаданные файлов.


## Документы, СМС и Интернет-банк

После проверки анкеты: «Документы для подписания» → «Подтверждение подписания заявления» → «Документы успешно подписаны» → «Уважаемый клиент». Формулировки экранов сохранены по предоставленным скриншотам. Дополнительной сводки в интерфейсе нет.

Заявление генерируется локально в PDF с кириллицей из ответов и полных текстов согласий соответствующего типа клиента. В списке также показаны реальные выбранные файлы. Доступны просмотр, скачивание, возврат к анкете, ошибка подготовки и повторная попытка. PDF — демонстрационный документ, не официальный банковский бланк.

СМС не отправляется. В прототипе принимается любая комбинация из шести цифр, включая 000000. Если цифр меньше шести, ошибка отображается под полем. Повторная отправка доступна через 3 минуты, отсчёт учитывает время в фоновой вкладке. Проверка после кода длится 3,5 секунды и автоматически открывает финальный экран. Это локальная имитация, без юридического подписания, банковской проверки, создания счетов и выдачи логина/пароля. Состояние очищается при перезагрузке.

Кнопка финального экрана открывает https://dbo2.bveb.by/ в новой вкладке. Учетные данные или СМС-код туда не передаются.
